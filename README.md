# claim-hub — 보험금청구 니치사이트 프로젝트

`research.csv`(zucca100/더픽 GA4 데이터) 분석에서 나온 "보험금청구 바로가기" 카테고리(RPM $72.9, 전체 1위)를
실제 사이트로 만드는 작업. 2026-08-05 세션에서 시작해 임시 scratchpad에 있던 걸
2026-08-06에 이 폴더로 옮김.

## 파일 구성

- `report.html` — 1차 분석 리포트(애드센스 니치사이트 확장 전략). claude.ai 아티팩트 원본:
  https://claude.ai/code/artifact/60750413-72fd-42d5-ad64-23dba98bad00
- `claim-hub-prototype.html` — 보험금청구/고객센터 "바로가기 허브" 프로토타입 사이트 (단일 HTML,
  Pretendard 폰트 base64 임베드)
- `scripts/` — `research.csv` 분석 및 리포트/프로토타입 생성 스크립트
  - `analyze.py`, `analyze2.py`, `inspect.py` — 데이터 탐색
  - `build.py`, `build2.py` — 리포트/프로토타입 HTML 빌드 (font base64 삽입 포함)
  - `b64.py`, `font_b64.py` — 폰트 base64 인코딩 유틸
- `data/` — 분석 중간 산출물(tsv) + 원본 `research.csv` 사본
- `assets/fonts/` — Pretendard woff2 원본 (base64 인코딩 전 소스)

## 현재 상태 / 다음 할 일

2026-08-06: `claim-hub-prototype.html`이 다크 톤으로 보인다는 피드백 원인을 확인해보니, 실제로는
`@media (prefers-color-scheme: dark)`가 `data-theme="light"` 없이 걸려있어서 **시스템이 다크모드면
자동으로 어두운 팔레트로 전환**되던 것이었음 (원래 라이트 팔레트 자체는 문제없었음). 이 프로토타입엔
다크/라이트 토글이 없으므로 다크 오버라이드 블록(`@media` + `:root[data-theme="dark"]`)을 통째로
제거해서 항상 라이트 팔레트로 고정함. 겸사겸사 `<!DOCTYPE html>`/`<meta charset="utf-8">`이 없어서
서버로 서빙할 때 한글이 깨지던 것도 같이 고침 (로컬 파일 더블클릭으로 열 때도 안전하도록). 이 두
수정사항은 `scripts/build2.py`의 `TEMPLATE` 자체에도 반영해둠 — 이전엔 최종 HTML 파일에만
수동으로 패치되어 있어서 스크립트를 재실행하면 버그가 되살아나는 상태였음.

같은 날 오후, 생명보험 5개사·손해보험 12개사(17개)뿐이던 목록을 금융감독원 산하 생명보험협회
(klia.or.kr)·손해보험협회(knia.or.kr) 정회원사 명단을 기준으로 생명보험 22개사·손해보험
16개사(총 38개사)로 확장함. 신규 21개사는 대부분 공식 홈페이지 최상위 도메인만 확인된
"홈페이지 바로가기"(`data-level="home"`) 상태이고, 서울보증보험만 보상안내(보험금 청구) 서브
페이지 딥링크까지 확인해 `data-level="direct"`로 넣음. GA사(한화생명금융서비스 등 협회 준회원 중
다른 보험사 상품을 중개만 하는 곳)와 재보험사(코리안리 등)는 소비자가 직접 청구할 대상이

메리츠화재 5개사로 이전되어 더 이상 독립 청구 창구가 없으므로 목록에서 제외.
